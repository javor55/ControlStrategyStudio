# File format

A project is a folder of plain text files — YAML for structure, Markdown for
documentation. It is the source of truth: the editor reads and writes these files and
nothing else, so they can be reviewed, diffed and merged with ordinary tools.
JSON Schemas of all YAML kinds are in [`../schema/`](../schema) (generated by
`npm run schemas`).

## Folder layout

```
project.yaml                         project settings
README.md                            project introduction
library/
  std/                               standard library (shipped with the app)
    library.yaml
    PID@1.0.0.yaml                   one file per version of a block type
  acme/                              your own library — a self-contained folder
    library.yaml
    DUTY_STANDBY@1.0.0.yaml          composite block type (inner diagram)
strategies/
  ACME/Ostrava/Dosing/U210/          free folder hierarchy (= plant hierarchy)
    README.md                        description of this level
    AIC215.yaml                      continuous strategy
    AIC215.md                        its function description
    BATCH_T210.seq.yaml              sequence
    BATCH_T210.md                    its function description
assets/                              images used in the documentation
.git/                                version history (in a folder or ZIP)
```

* The folder names under `strategies/` form the hierarchy. Level names (Site,
  Area, Unit …) are only labels configured in `project.yaml`.
* Strategy and sequence names share one name space in the project and must equal the
  file name (`AIC215.yaml` → `strategy: AIC215`).

## Common rules

* **`format: csd-<kind>/<version>`** at the top of each file —
  `csd-project/1`, `csd-library/1`, `csd-blocktype/1`, `csd-strategy/1`,
  `csd-sequence/1`. Older versions are migrated on load; a file from a newer version
  of the tool is refused rather than damaged.
* **`uid`** — a stable identity that survives renames and moves (written by the
  editor).
* **`x-…` keys** are allowed everywhere and kept untouched — room for data of other
  systems (`x-dcs-area: 12`).
* **Names** of blocks, ports, steps: letters, digits and `_` (blocks also `-`),
  not starting with a digit.
* **Durations** are written as `100ms`, `5s`, `10min`, `4h`.
* Comments (`# …`) and formatting survive every edit made by the editor.

## project.yaml

```yaml
format: csd-project/1
name: Dosing & CIP Plant Ostrava
description: Caustic dosing, batch preparation and CIP of line U310
author: J. Novák
levels: [Enterprise, Site, Area, Unit]     # names of folder levels (optional)

drawing:
  params: show                             # parameters on blocks by default: show | hide
  feedback: { mark: true, style: dashed }  # previous-cycle (feedback) links

signal_categories:                         # line categories for links (optional)
  default:   { color: "#1d2328", width: 1.2 }
  interlock: { color: "#b3261e", style: dashed, description: Trips and permissives }
  tracking:  { color: "#1f5f8b", style: dotted }

title_block:                               # printed in PDF / HTML title blocks
  logo: assets/logo.svg
  drawn: J. Novák
  checked: P. Svoboda
  approved: M. Dvořák
```

Line styles: `solid`, `dashed`, `dotted`, `dashdot`; width 0.5 – 6.
`default` styles every link without a category.

## Libraries and block types

`library/<name>/library.yaml`:

```yaml
format: csd-library/1
name: acme
version: 1.2.0
description: Company standard blocks shared across ACME plants
```

`library/<name>/<TYPE>@<version>.yaml` — one file per version of a block type:

```yaml
format: csd-blocktype/1
type: DUTY_STANDBY
version: 1.0.0
category: Devices                  # group in the palette
kind: composite                    # basic (default) | composite
color: "#e3eef6"                   # optional header colour
description: Two pumps, one duty and one standby, with automatic changeover
inputs:
  - { name: RUN, type: BOOL, description: Run request }
  - { name: INTLK, type: BOOL, default: true, description: FALSE trips both pumps }
outputs:
  - { name: CMD_A, type: BOOL }
  - { name: FAULT, type: BOOL, description: Both pumps failed }
params:
  - { name: FB_TIME, type: TIME, default: 5s, unit: s }
  - { name: MODE, type: ENUM, values: [AUTO, MAN], default: AUTO }

implementation:                    # basic blocks: optional reference implementation
  language: ST
  source: |
    CMD_A := RUN AND INTLK;

diagram:                           # composite blocks: the inner diagram
  blocks:
    MA: { type: MOTOR, params: { FB_TIME: $FB_TIME } }   # $PARAM = parameter of the composite
  links:
    - in.RUN -> MA.START           # in.X / out.X = the composite's own ports
    - MA.FAULT -> out.FAULT
```

Port fields: `name`, `type`, `description`, `default`, `unit`, `values` (allowed
values), `visibility: always | connected` (hide rarely used ports until connected).

## Continuous strategy (`NAME.yaml`)

```yaml
format: csd-strategy/1
strategy: FIC101
title: Inlet water flow control
description: Controls the inlet flow; setpoint from the level controller.
revision: B
author: J. Novák
scan: 500ms                        # default scan of all blocks

sheets:                            # optional — one sheet by default
  - { id: 1, title: Flow control }
  - { id: 2, title: Valve }

blocks:
  FT101:
    type: AI                       # TYPE (latest) · TYPE@1.0.0 (pinned) · lib/TYPE
    description: Inlet flow transmitter
    order: 10                      # execution order
    params: { PV_HI: 50, UNIT: m3/h }
  FIC101:
    type: PID@1.0.0
    order: 20
    scan: 100ms                    # own scan (overrides the strategy scan)
    params: { GAIN: 0.8, TI: 12s, SP_EXT_ON: true }   # parameters and input constants
    comment: Tuning from loop test during FAT.
  FV101:
    type: AO
    order: 30
    sheet: 2
    pos: [640, 140]                # stored only after the block was moved by hand
    display: { params: false }     # hide parameters on this block

links:
  - FT101.PV -> FIC101.PV                       # short form
  - from: LIC100:LIC100.MV                      # source in another strategy
    to: FIC101.SP_EXT
    comment: Cascade setpoint
  - { from: FIC101.QH, to: FV101.INTLK, category: interlock, label: High flow trip }
  - { from: Level control T200, to: FIC101.TRK_VAL, planned: true }   # planned link
  - FIC101.MV -> FV101.IN

notes:
  - { text: "Valve FV101 fails closed.", sheet: 2, pos: [600, 40] }
```

* A link goes from an **output** to an **input** of this strategy; the source may
  also be `STRATEGY:BLOCK.PORT` in another strategy or a sequence signal. Links never
  write into another strategy — they only pull signals.
* Each input has at most one driver. An input with a link and a constant uses the
  link (warning).
* **Planned links** (`planned: true`) mark a connection whose other end is not drawn
  yet; that end is free text or `STRATEGY:BLOCK.PORT`. Once it exists the validator
  says so, and one click turns it into a real link.
* Link fields: `from`, `to`, `label`, `comment`, `category`, `planned`, `x-…`.

## Sequence (`NAME.seq.yaml`)

```yaml
format: csd-sequence/1
sequence: BATCH_T210
title: Batch preparation in T210
scan: 1s

inputs:                            # own inputs (commands from the operator / other systems)
  - { name: START_CMD, type: BOOL, description: Operator starts a batch }

steps:
  S0:
    initial: true
    description: Idle
  S10:
    description: Fill water
    actions:
      - { q: P1, set: FIC211:FQ211.RESET }          # write an input of a strategy
      - { q: S,  set: FIC211:FIC211.SP_EXT_ON }
      - { q: N,  set: TIC213:TIC213.SP_EXT, value: 65 }
      - { q: D,  text: Take a sample, time: 15min } # described in words only
    time: { min: 1min, max: 10min }                 # supervision times
  S20: { description: Heat, sheet: 2 }

transitions:
  - { from: S0, to: S10, condition: START_CMD and LIC210:LS210E.LT }
  - { from: S10, to: [S20, S25], condition: LIC210:LS210A.GT }   # parallel branch (fork)
  - { from: [S22, S27], to: S30, condition: S22.T > 10s }         # join
  - { from: S50, to: S80, condition: LAB_REJECT, comment: Rejected }
```

* **Action qualifiers** (IEC 61131-3): `N` while active, `S` set, `R` reset, `P1`
  pulse on entry, `P0` pulse on exit, `D` delayed, `L` limited (`D` / `L` need
  `time`). `set:` names `STRATEGY:BLOCK.PORT`; non-BOOL inputs need `value`.
* **Conditions** use `and`, `or`, `not`, comparisons (`< <= > >= == !=`),
  arithmetic, durations and signals: strategy outputs (`LIC210:LS210A.GT`), the
  sequence's own inputs, step flags `S20.X` (active) and `S20.T` (time active).
* **Branches** — a transition to several steps starts a parallel branch, from several
  steps it joins; several transitions from one step form an alternative branch.
* **Sequencers** — several step chains in one sequence, each with a start condition
  and a priority:

  ```yaml
  state_model: isa88               # optional: SEQ.RUNNING, SEQ.HOLDING … as signals
  sequencers:
    - { id: RUN,   title: Running,  start: SEQ.RUNNING,  priority: 1 }
    - { id: HOLD,  title: Holding,  start: SEQ.HOLDING,  priority: 2 }
  steps:
    S0: { initial: true }                   # no sequencer = the first one
    H0: { initial: true, sequencer: HOLD }
  ```

  Without `sequencers` there is one implicit sequencer `MAIN`. Details and reasoning:
  [design/sequences.md](design/sequences.md).

## Signals and references

| Written as | Means |
|---|---|
| `BLOCK.PORT` | port of a block in the same strategy |
| `STRATEGY:BLOCK.PORT` | output of a block in another strategy |
| `SEQUENCE:S20.X` / `SEQUENCE:S20.T` | step of a sequence is active / time active |
| `SEQUENCE:SEQ.RUNNING` | state of a sequence (`SEQ.<STATE>`, ISA-88 states with `state_model: isa88`) |
| `in.PORT` / `out.PORT` | the composite's own ports inside a composite diagram |
| `$PARAM` | parameter of the composite inside a composite diagram |

## Documentation files

* `README.md` — the project introduction (root) or the description of a hierarchy
  level (in a folder).
* `NAME.md` next to `NAME.yaml` / `NAME.seq.yaml` — the function description.
* Markdown with tables, images from `assets/` and charts. All of it goes into the PDF
  and HTML exports.
